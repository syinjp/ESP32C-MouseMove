# ESP32-C3 MouseMove

ESP32-C3をBLE HIDマウスとして動作させるESP-IDFプロジェクトです。PCとペアリングすると、接続完了から3秒後に小さな四角を1回描き、その後は既定で60秒ごとに同じ動きを繰り返します。4方向の相対移動を行うため、通常は元の位置へ戻ります。

## 開発環境

- ボード: ESP32-C3（内蔵USB-Serial/JTAG）
- ESP-IDF: v5.5.5
- ターゲット: `esp32c3`
- Bluetooth: BLE HID / NimBLE（Bluetooth Classicは使用しません）

## ビルド

ESP-IDF v5.5.5の環境を有効にしたターミナルで、プロジェクトのルートへ移動して実行します。COMポートはビルドだけなら不要です。

```console
idf.py build
```

ペアリング鍵の永続保存には `CONFIG_BT_NIMBLE_NVS_PERSIST=y` が必要です。新規構成では `sdkconfig.defaults` で有効になりますが、既存の `sdkconfig` がある場合は、その設定が優先されます。旧版から更新する場合は、`idf.py menuconfig` で `BT_NIMBLE_NVS_PERSIST` を検索し、`Persist the BLE Bonding keys in NVS` を有効にして保存してからビルドしてください。

### ホスト上の回帰テスト

Python 3とGCCをPATHから実行できる環境で、接続準備状態・サスペンド中の待機・初回移動までの待ち時間を確認できます。実際の関数を抽出してコンパイルし、スケジューラーなどを模擬するテストです。実機のBluetooth通信やFreeRTOSの動作を検証するものではありません。

```console
python -B -m unittest discover -s tests -v
```

## 設定変更

次のコマンドで `MouseMove Configuration` を開きます。

```console
idf.py menuconfig
```

変更できる項目:

- Bluetooth表示名（既定: `ESP32-C3 MouseMove`）
- 自動移動の間隔（既定: 60秒）
- 1ステップの移動量（既定: 3）

## 書き込みとペアリング

実際のCOMポートを確認したうえで、次の `COMx` を置き換えて書き込みます。

```console
idf.py -p COMx flash monitor
```

Windowsでは「設定」→「Bluetoothとデバイス」→「デバイスの追加」から `ESP32-C3 MouseMove` を選択します。PIN入力は不要です。鍵の永続保存を有効にした構成では、ボンディング情報がESP32-C3のNVSに保存されます。切断後は自動で再接続待ちになりますが、接続を開始するのはPC側です。

同時に接続できるPCは1台です。複数のPCに登録している場合は、試験対象以外のPCが接続を取り直さない状態にしてください。

### 旧版からの更新

旧版では鍵の永続保存が無効で、ESP32-C3側の鍵はRAMにしか保持されませんでした。更新後は、問題が発生するWindows 11 PCのBluetoothデバイス一覧から `ESP32-C3 MouseMove` を一度削除し、再ペアリングしてください。これにより、PCとESP32-C3の双方に新しいペアリング情報を登録します。

HID定義や機器名を変更した後に認識がおかしい場合は、Windows側のBluetoothデバイス一覧から一度削除して再ペアリングしてください。

### 再接続の確認

更新後の再接続改善は、実際に問題が発生するPCで確認してください。最初の再ペアリング後は登録を削除せず、次を個別に試します。

- ESP32-C3の電源を入れ直した後の再接続
- PCを再起動した後の再接続（ESP32-C3は別電源で動作を継続）
- Bluetoothの切断・再接続
- PCのスリープ・復帰後の再接続とマウス動作

接続状態だけでなく、接続完了後にマウス移動が再開することも確認します。失敗した場合は、操作時刻と、起動・接続・暗号化・切断に関するログを記録してください。ログ採取の開始操作でボードがリセットされる場合があるため、リセットの有無も記録します。ログには接続相手のBluetoothアドレスなどが含まれる場合があります。公開する前に、機器を識別できる情報を伏せてください。
